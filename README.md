# perl-wasm

[wasmify](https://github.com/goccy/wasmify) project that compiles
[Perl](https://github.com/Perl/perl5) (v5.42.2) to `wasm32-wasip1` and emits
the pure-Go (wasm2go) bindings [go-perl](https://github.com/goccy/go-perl)
consumes.

## Outputs

The CI workflow at `.github/workflows/build.yml` and the local `make wasm`
target both produce, from a clean checkout:

| File | Where | What |
| --- | --- | --- |
| `perl.wasm` | `.wasmify/wasm-build/output/perl.wasm` | The wasi-sdk-built Perl interpreter — libperl.a plus every static XS extension, behind the thin embedding API in `perl.cc` — optimised by binaryen wasm-opt. |
| `perl_wasm2go.tar.gz` | `build/wasm2go/internal/internal/wasm2go/` | The transpiled pure-Go bundle, a self-contained Go module (`github.com/goccy/perlwasm2go`). go-perl downloads and extracts it. |
| `perl_wasm2go.go` | `build/wasm2go/internal/perl.go` | `protoc-gen-wasmify-go`'s wasm2go bridge. |
| `perl_stdlib.zip` | generated by `scripts/make-stdlib-zip.py` | Trimmed copy of the **assembled** `perl5/lib/` tree (the pure-Perl stdlib: strict/warnings, the dual-life modules, the generated `Config.pm`, the unicore/ tables), locked to the pinned perl5 submodule version. go-perl unpacks it and passes it to `perl_new(lib_dir)` as `@INC`. |

Everything above is **regenerated** on every build; only the inputs below are
committed.

## Committed inputs

```
wasmify.json            # wasmify decisions: project metadata, build_commands, bridge config
perl5/                  # git submodule pinned to the upstream commit we build against (v5.42.2)
buf.yaml                # buf module
buf.gen.yaml            # protoc-gen-wasmify-go invocation (wasm2go bundle)
proto/wasmify/          # wasmify proto options the generated proto imports
perl.cc, pl.h           # the thin C++ embedding API (perl_new / perl_eval / perl_close / perl_interrupt_addr)
scripts/wasi-configure.sh   # the Perl-specific configure phase (host miniperl + wasm cross-configure + lib/ assembly)
scripts/host-miniperl.sh    # builds a HOST-native miniperl + generate_uudmap (Perl runs miniperl during its own build)
scripts/wasi-posix-shim.h   # declarations wasi-libc lacks but Perl's core references (force-included via ccflags)
scripts/make-stdlib-zip.py  # zips the assembled perl5/lib into perl_stdlib.zip
docs/xs-modules.md      # which XS extensions are linked statically, excluded, and why
```

Everything else (`build.json`, `api-spec.json`, `proto/perl.proto`, `bridge/`,
`build/`, `perl.wasm`, `perl_stdlib.zip`) is in `.gitignore` and reproduced by
`make wasm`.

## Building locally

The full pipeline runs inside a wasmify image bundling wasi-sdk, binaryen, buf,
and the wasmify CLI — you install none of those on your host:

```sh
make wasm                              # uses ghcr.io/goccy/wasmify:v0.4.10
make wasm DOCKER_PLATFORM=linux/amd64  # on Apple Silicon (the image is amd64-only)
make wasm-clean                        # drop regenerated outputs, keep committed inputs
```

`make wasm` runs (under `docker run --rm -v $PWD:/work …`) the same sequence as
CI. Perl needs a configure phase first: the build RUNS miniperl for build-time
code generation (Config.pm, the Unicode tables, the MakeMaker-driven extension
builds), and a wasm miniperl cannot run on the build host — so
`scripts/wasi-configure.sh` first builds a host-native miniperl of the same
Perl version (the analogue of python-wasm's host build-python), then generates
the wasm32-wasi `config.sh` and assembles `perl5/lib`:

```
make tools                  # ensure wasi-sdk (pre-baked in the image)
scripts/wasi-configure.sh   # host miniperl + wasm cross-configure + lib/ assembly
wasmify build               # replay the captured `make` (libperl.a + all extensions)
wasmify generate-build      # build.log -> build.json
wasmify parse-headers       # pl.h -> api-spec.json
wasmify gen-proto           # api-spec.json -> proto/ + bridge/
wasmify wasm-build --optimize   # build.json + bridge -> perl.wasm + wasm-opt
buf generate                # proto/ -> build/wasm2go/ (the wasm2go bundle)
make bundle-gomod           # stamp the bundle's go.mod
```

The stdlib zip must be built from the **assembled** `perl5/lib` (i.e. after the
pipeline has run) — a pristine checkout's `lib/` holds only the core modules,
without the dual-life modules and the generated `Config.pm`:

```sh
make stdlib-zip             # perl5/lib -> perl_stdlib.zip
```

## CI

`.github/workflows/build.yml` runs the pipeline inside the wasmify image on
pull requests and pushes to `main`: it uploads the artefacts, attaches
`actions/attest-build-provenance` SLSA attestations (push events on a public
repo), and maintains a ghcr cache image keyed on the wasmify image tag + the
perl5 submodule SHA so warm runs finish incrementally — and a wasmify upgrade
automatically misses the old cache. Pull-request runs read the cache but never
write it and never publish.

`.github/workflows/release.yml` runs on `v*` tags only: it rebuilds from the
tagged source and publishes `perl.wasm`, `perl_wasm2go.go`,
`perl_wasm2go.tar.gz`, `perl_wasm2go.sha256` (per-file digest manifest of the
tarball, attested via `subject-checksums` so any extracted file verifies
individually), and `perl_stdlib.zip` as Release assets.
